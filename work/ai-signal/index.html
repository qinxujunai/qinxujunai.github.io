为什么要做

AI 的信息太多了：推文、播客、博客、论文、GitHub，每天几百条，真正值得看的不到 5 条。刷信息流费时间，还容易被情绪和噪音带着走。

我想要一位靠谱的编辑：每天替我读一遍，只留下会改变判断的东西。

难在哪里

  • “重要”很难定义。让模型自由发挥，它会把每一条都写得很重要。
  • 模型的输出不稳定：JSON 偶尔不合法，接口偶尔超时。一封每天必到的邮件，不能因为一次解析失败就断掉。
  • 信源各不相同：有的要 API key，有的只有网页。

边界

做

  • 聚合公开信源
  • LLM 策展，中英双语摘要
  • 每天一封邮件，每条附原文链接

不做

  • 需要 X、YouTube 的 API key
  • 做 App 和账号体系
  • 替读者下结论：没有链接的内容一律不收

架构

  1. 1定时

    • GitHub Actions cron
    • 每天北京时间 10:00

  2. 2抓取 · prepare-digest

    • X 推文 · 播客 · 博客
    • HN · ArXiv · GitHub Trending
    • 中文 AI 媒体
    • 预过滤

  3. 3策展 · remix-digest

    • DeepSeek 按“三问”筛选
    • 严格 JSON 输出
    • 解析失败：修复 → 重试 → 模板兜底

  4. 4送达 · deliver

    • SMTP 邮件
    • 4 小时冷却，防止重复发送
    • 👍 有用 / 👎 没用

三个脚本只通过 JSON 和 HTML 文件交接，不依赖 shell 管道，任何一步都能单独重跑。

编辑标准写在提示词里，每条内容必须过三问：读者会因为这条信息做出不同的决策吗？这是真正的洞察，还是噪音？没有 URL = 不存在。

我放弃了什么

  • 用 DeepSeek 的 chat 模型

    原因每天约 $0.002，一年约 $0.73；推理模型每天约 $0.01

    放弃的方案更强也更贵的推理模型

  • 跑在 GitHub Actions 上

    原因公开仓库免费，不需要一台一直开着的电脑

    放弃的方案自己的服务器或本地定时任务

  • 推文和播客用开源的 follow-builders feed

    原因不需要 X、YouTube 的 API key

    放弃的方案自己维护一套爬虫

  • 发邮件

    原因打开就能看，不用再装一个东西

    放弃的方案自建阅读 App

怎么证明它可靠

  • 解析失败有三层兜底：先清理再解析；失败就带着错误信息重试一次；再失败，用模板直接渲染原始条目。邮件照常发出。
  • 4 小时冷却，同一天不会重复发送。
  • 仓库自带信源健康检查脚本，哪个信源断了，一跑就知道。

还差什么

  • 推文、播客和博客依赖第三方的 follow-builders feed，它一停，这几类就会断。
  • 按兴趣过滤的函数写好了，还没接进流程；目前兴趣只作为提示词里的偏好。
  • 👍 / 👎 的反馈还没有反过来调整筛选标准。
