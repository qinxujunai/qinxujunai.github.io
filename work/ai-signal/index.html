每天几百条，只留下会改变判断的

AI 的信息太多：推文、播客、博客、论文、GitHub，每天几百条。难的不是看到，是分清哪些来自可信的来源、哪些是真正有价值的，而不是噪音。GitHub 上的好项目，我也想第一时间知道它能解决什么问题。

我觉得在 AI 时代，提出一个好问题会越来越重要；好问题背后是判断力，判断力靠长期吃进好的信息。所以我想要一位靠谱的编辑：每天替我读一遍，只留下会改变判断的内容，几分钟读完。

模型写不出一个假链接

模型会编。让它自己写链接和数字，迟早会出现一个看起来很真的假链接。所以每条素材先编号，模型只能引用编号；链接、分数和 star 数由程序按编号填回，编号不存在的那一条直接丢掉。

10:00 整，不早不晚

GitHub 的定时任务高峰期会晚好几个小时：10-22 定在 09:41 的任务，14:32 才开始跑。现在从凌晨四点起每 20 分钟排一次队，第一个启动的认领当天，09:35 读完、编好，等到 10:00:00 发出；其余的看到已经发过，就自己退出。

10-23 那期：10:00:00 开始发送，10:00:03 发完。

白底黑字，一页读完

排版参照 Apple 的新闻邮件和 Stratechery：白底黑字，层级只靠字号、字重和留白，全期只有链接一种颜色。开头是当天最重要的一件事和三条「30 秒读完」，每条下面一行写着来源、讨论和信号强度。

技术细节边界、架构、取舍、验证、历程

边界

做

  • 聚合公开信源
  • 按写死的编辑标准挑选、合并、改写
  • 每天一封邮件、一期网页版和 RSS，每条都附原文

不做

  • 需要 X、YouTube 的 API key
  • 做 App 和账号体系
  • 追踪读者：没有像素，没有点击统计

架构

  1. 1排队

    • 北京时间 04:07 到 09:47，每 20 分钟排一次
    • 第一个启动的任务认领当天，其余看到就退出

  2. 2收集 · 09:35

    • X 上的 builder、播客（follow-builders）
    • OpenAI、Anthropic、DeepMind、Google AI、Qwen 等官方博客
    • Hacker News、Techmeme、Reddit（经 AINews 汇总）
    • 论文热榜、Hugging Face 热门模型、GitHub 今日趋势、Product Hunt
    • 量子位、36氪
    • 去掉 60 天内发过的

  3. 3编号

    • 每条素材一个编号：H3、R1、M2…

  4. 4编辑 · DeepSeek

    • 按「三问」挑选，多来源合并
    • 只输出 JSON，只能引用编号

  5. 5回填

    • 代码按编号填回链接、分数、star 数
    • 编号不存在，这条直接丢弃
    • 模型失败：按热度排出降级版

  6. 6送达 · 10:00

    • 等到 10:00:00 发出，发之前再查一次今天发过没有
    • 邮件主题就是当天的标题
    • 同时发布网页版和往期

编辑标准写在提示词里，每条内容必须过三问：读者会因为这条信息做出不同的决策吗？这是新的事实，还是噪音？有没有具体的数字或名字？

排版参照 Apple 的新闻邮件和 Stratechery：白底黑字，层级只靠字号、字重和留白，全期只有链接一种颜色。开头是期号、当天最重要的一件事和主编的一句话；头条写「为什么重要」；每条下面一行写分类、信号强度（●●○）、来源和讨论；之后是社区在聊、观点、新模型、新产品、论文、开源、快讯。

信号强度：几个独立来源报道了同一件事，或者社区里讨论得有多热，最多三个点。

取舍

  • 模型只引用编号，不写链接

    原因链接和数字最容易被编造；由代码回填，至少保证它们真实存在

    放弃的方案让模型直接写，再事后校验

  • 每天发布一期网页版

    原因既是存档，也让定时任务不会因为 60 天无活动被暂停

    放弃的方案只发邮件，不留痕迹

  • 去掉 👍 / 👎 和追踪像素

    原因接收反馈的服务早已返回 404，留着就是坏链接

    放弃的方案假装有反馈回路

  • Hacker News 改用 Algolia，按整词匹配

    原因旧做法只看首页 30 条，按子串匹配，「said」也会被当成 AI

    放弃的方案首页接口

  • 凌晨起每 20 分钟排一次，先认领再等到 10:00

    原因只用 GitHub 就能吃下几个小时的延迟，不用另租服务器

    放弃的方案外部定时服务去触发

  • Reddit 经 AINews 的每日汇总

    原因直接请求被 403；AINews 每天整理 Reddit 热帖，带讨论热度

    放弃的方案登录 Reddit 接口，要管账号和密钥

  • 用 DeepSeek 的 chat 模型

    原因一年几美元

    放弃的方案更贵的推理模型

验证

  • v3 第一期（2026-10-20）从 60 条新内容里选出 30 条，自动发信，并发布网页版和往期。
  • 链接和数字全部来自原始数据；模型引用了不存在的编号，这条就不会出现。
  • 模型无响应时照样发出一期，按来源热度排序，并在邮件里写明；某个信源挂了，页脚会写出来。
  • 发过的链接记录 60 天，下一期不会重复。
  • 8 组自动测试：各信源的解析、热度、北京时间的计算、配色上限，以及网站和 RSS；每次提交都在云端跑一遍。
  • 准点：2026-10-23 那期，北京时间 10:00:00 开始发送，10:00:03 发完；同一早上排队的另一次运行看到已发，自动退出，没有重复发（GitHub 运行记录）。

历程

  1. 2026.05第一版：follow-builders 的推文和播客，LLM 策展，邮件送达
  2. 2026.05.22v2：加入 Hacker News、ArXiv、GitHub、中文媒体
  3. 2026.07.22最后一次自动发送；之后定时任务因 60 天无提交被暂停
  4. 2026.10.20v3：重写信源、编辑方式和排版，恢复每日发送
  5. 2026.10.22v4：10:00 整送达；加入 Techmeme、Reddit、热门模型、Product Hunt、Anthropic、Qwen、36氪；版式改成白底黑字，只留链接一种颜色
  6. 2026.10.23v4.1：有了自己的网站，打开先看到它是什么和今天这期的要点；加上 RSS、开源许可和版本发布

还差什么

  • 推文和播客仍依赖第三方的 follow-builders feed，它一停，这两类就会断。
  • 准点靠 GitHub 在早上把十几次排队里的任意一次及时启动；一次都没轮上，那天就由 10 点以后的补发兜底，会晚。
  • Reddit 依赖 AINews 的汇总，它哪天停更，社区这一栏就会空。
  • 没有读者反馈回路；编辑标准只能靠人读了再改。
  • 模型可能引错编号：链接是真的，但不一定配对。第一期里也还有「正面挑战」「标志性」这类编辑标准不允许的评语。
