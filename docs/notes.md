# 写下的（朋友圈）· 填写说明与设计规范

写给在他电脑上往这里加朋友圈的 ChatGPT / Codex，也写给以后接手的人。**只改数据，不改代码和样式**；照这份文档做，页面就和现在一样好看。

- 首页位置：健身之后、结尾的信之前，`#notes`。
- 全文页：`/notes/`（英文 `/en/notes/`，正文仍是中文）。
- 公开站：https://qinxujunai.github.io/#notes
- 求职站：https://qinxujun.praxisai.online/#notes

## 一、它长什么样（2026-10-26，参照 apple.com 的横滑卡片和 iOS 的底部弹层）

他的原话：「像一个进度条，里面最经典的是一句话，他感兴趣就可以点进去看全文」。

1. 小字「朋友圈」、大标题「这些年写下的」，下面一行「每条一句 点开看全文」。
2. 一排横着滑的卡片，**最早的在最左边**，往右越来越新。每张卡片只有三样东西：
   - 日期（灰色小字）；
   - 他这条里最经典的那**一句话**（大字）；
   - 「读全文 ›」。
3. 卡片上方是年份（2019、2020……）：点一个年份，就滑到那一年的第一条。只有一年时不显示。
4. 卡片下方是一条细线（进度条）和左右两个圆按钮，表示滑到了哪里。卡片放得下、不用滑的时候，这一排不显示。
5. 点一张卡片：手机上从底部升起一个弹层，电脑上是居中的面板。里面是这一条的全文，卡片上那句话加粗。弹层底部是「‹ 上一条」「下一条 ›」，右上角「完成」。按 Esc 或点暗处也能关。
6. 「全部 N 条 ›」去 `/notes/`：按年份分组，每条全文，没有 JavaScript 也能看。

## 二、怎么加一条（只改这一个文件）

文件：`src/notes.json`。它是一个数组，每条一个对象，**顺序无所谓**，构建时按日期排。

### 模板（复制这一段，改四个值）

```json
{
  "id": "2024-03-12-reading",
  "date": "2024-03-12",
  "quote": "这里放原文里的一句话，一字不改",
  "text": "这里放这条朋友圈的全文。\n\n空一行（两个 \\n）就是新的一段。"
}
```

### 每个字段的规矩

| 字段 | 必填 | 规矩 |
| --- | --- | --- |
| `id` | 是 | 只用小写英文字母、数字、`-`。写成「日期-两三个英文词」，例如 `2024-03-12-reading`。一旦发出去就不要改（链接 `/notes/#n-<id>` 会失效）。不能和别的重复 |
| `date` | 是 | `YYYY-MM-DD`；只知道月份就写 `YYYY-MM`。用朋友圈显示的发布日期，不要猜日子 |
| `quote` | 是 | 这一条里**最经典的一句话**，从 `text` 里原样复制。构建会检查它是不是一字不差地出现在 `text` 里（只忽略空格和换行），不是就报错停下。不加引号、不加句号，不改写、不拼接两处原文 |
| `text` | 是 | 朋友圈全文，**一字不改**：错别字、口语、中英混排、括号都保留。段落之间用 `\n\n`，段内换行用 `\n`。只放纯文字，不放 HTML、图片、表情图、评论、点赞 |
| `home` | 否 | 写 `false` 时，这条不出现在首页那一排，只在 `/notes/` 里。条数多了首页超出体积预算时才用（见第五节） |

### 怎么挑那「一句话」

- 能单独读懂：不看前后文，也知道在说什么。
- 是他自己的判断或发现，不是转述别人、不是描述当天做了什么。
- 长度：中文 15–60 个字最好看（卡片里 3–4 行）；超过 80 个字就挑更短的一句。
- 一条里有好几句都好，挑一句，其余留在全文里（全文页会把这句加粗）。
- 原文是英文和中文连在一起的（例如「Attention is all you need. 把注意力……」），可以连着取，只要原文就是这样连着的。

## 三、哪些放、哪些不放、放在哪个站

**「网站」有两个，每次都要想到两边**（他 2026-10-26 说的）：

- 公开站（本仓库，`qinxujunai.github.io`）：会发朋友圈，领导、同事都会看到。
- 求职站（私有仓库 `qinxujunai/portfolio`，`qinxujun.praxisai.online`）：只发给招聘方。它是用本仓库同一套代码生成的，所以 `src/notes.json` 里的每一条两边都有。

| 内容 | 放哪里 |
| --- | --- |
| 读书、学习、思考、AI、做东西、健身、生活感悟 | 本仓库 `src/notes.json`（两个站都有） |
| 讲工作、公司、同事、客户、跳槽、求职的 | **只放求职站**：写进私有仓库 `profile.mjs` 的 `moments` 数组（格式完全一样）。不要写进本仓库，本仓库是公开的 |
| 家人、健康、病情、感情、别人的名字或照片、地点定位、手机号、微信号、金额、年龄、毕业年份 | **都不放**，除非他明确同意某一条 |
| 转发的文章、只有图片没有文字的、只有一两个字的 | 不放 |
| 骂人、吐槽具体的人或公司的 | 不放 |
| AI 写的部分（例如他贴的 ChatGPT 生成的人物简介） | 删掉那部分，只留他自己写的。删在开头或结尾就直接删；删在中间用「……」 |

拿不准的，列出来问他，不要自己决定放。

## 四、加完以后怎么上线

```bash
# 在本仓库
git pull                      # 先拿 GitHub 上最新的
# 改 src/notes.json
npm run build                 # 生成页面；quote 不在 text 里、日期或 id 写错，这一步就会报错并说明是哪一条
npm run check                 # 体积、链接、隐私扫描等
npm run ship -- "写下的：加了 N 条朋友圈"   # 构建、检查、浏览器验收、提交、推送，一条命令

# 求职站（私有仓库 portfolio，和本仓库放在同一个上级目录）
cd ../portfolio
./build.sh && ./deploy.sh     # 需要 CLOUDFLARE_API_TOKEN、CLOUDFLARE_ACCOUNT_ID 两个环境变量，不进仓库
```

- 朋友圈的内容不受「文案锁定」（`copy.lock.json`）管：它是他的原话，在构建时包在 `<!--live-->` 里，加条目不用 `npm run lock`。板块的标题、按钮文字仍然锁定，要改得先问他。
- 提交只署他本人（作者 qinxujunai，邮箱用他 GitHub 账号的 noreply 地址，见 AGENTS.md「红线」），不加 Co-Authored-By 之类的署名。

## 五、体积

首页的样式和内容都在一个文件里，`npm run check` 限制每页压缩后不超过 32KB。每十条朋友圈大约多 1KB。超了的时候，把一些旧的、没那么好的标 `"home": false`（它们仍在 `/notes/`），不要去改预算，也不要删别的板块。

## 六、设计规范（改代码的人看；只加数据的话不用碰）

代码：`scripts/build.mjs` 的 `notes()`、`notesPage()`；样式在 `assets/site.css` 末尾「写下的」一节；交互在 `assets/site.js`「写下的」一段。

**只用已有的颜色变量**，不加新颜色、渐变、阴影、图标、表情或动效：

| 东西 | 数值 |
| --- | --- |
| 区块 | 白底（`.tile.plain`），上下 56px（≥734px 宽 72px），内容居中 |
| 小字「朋友圈」 | 17px / 600 / `--muted` |
| 大标题 | `min(40px, 8.6vw)` / 600 / `--ink`，行高 1.1 |
| 副句 | 21px，行高 1.38，`--ink` |
| 年份按钮 | 15px / 600 / `--muted`，高 36px，左右 14px；当前年份 `--ink`，底色 `--soft`，圆角 18px |
| 卡片 | 底色 `--soft`，圆角 22px；手机宽 `min(84%, 380px)`、最低 300px 高、内边距 28/26/22px；电脑宽 380px、最低 340px 高、内边距 34/32/26px；卡片间距 16px；左对齐 |
| 卡片日期 | 14px / 600 / `--muted`，数字等宽 |
| 卡片金句 | 手机 21px、电脑 24px / 600 / `--ink`，行高 1.45 / 1.42，正常中文断行 |
| 「读全文 ›」 | 17px，`--link`，在卡片底部 |
| 进度条 | 2px 高，底色 `--hairline`，已滑过的部分 `--ink`，总宽最多 340px（含两个按钮） |
| 圆按钮 | 36px，底色 `--soft`，文字 `--ink`；到头那一侧变淡 |
| 弹层 | 底色 `--card`；手机贴底、上面两个角 20px、最高 88vh；电脑居中、宽 `min(640px, 100% − 48px)`、圆角 18px、最高 80vh；背后暗一层 `rgba(0,0,0,.4)` |
| 弹层正文 | 17px，行高 1.75，`--body`；段距 14px；金句加粗、`--ink` |
| 动效 | 弹层手机上升 0.42s `cubic-bezier(.32,.72,0,1)`，电脑淡入放大 0.3s `cubic-bezier(0,0,.5,1)`；卡片悬停（只在有鼠标时）放大 1.016；「减少动效」时全部没有 |

文字规矩和全站一样（`docs/copy.md`）：标题副句不带句号，不对读者说「你」，不说教。**朋友圈原文不受这几条限制**：它是他署名的原话，一字不改。

## 七、不要做的

- 不改他的原文，不「润色」，不补标点，不改错别字。
- 不为了好看编一句不在原文里的话做金句。
- 不放图片（朋友圈的配图有别人、有地点，也会拖慢页面）。
- 不加评论、点赞、分享按钮，不接任何外部服务（全站零外部请求）。
- 不按「热门」「精选」重新排序：顺序只按时间。
- 不在本仓库放工作、公司相关的朋友圈（见第三节）。
