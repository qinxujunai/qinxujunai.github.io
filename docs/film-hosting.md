# 影片的视频放在哪、怎么换（2026-10-25）

《来不及爱你》在两个网站播放：个人网站首页首屏，和影片网站 `too-late-to-love-you`。两边播同一个文件：他自己导出的 4K 网页版，51,065,030 bytes，SHA-256 `bf20447b…768a8`、MD5 `cfa2405e94f83841b82b54084b82dbca`（全文见影片仓库 `src/hosts.json` 的 `file`）。**不转码、不重封装、不压缩，也永远不要提另出一个版本**（1080p、低码率之类；2026-10-24 他说「你这辈子都不要搞」）。

## 两套方案，一次只用一套
| 方案 | 播放 | 下载 | 特点 |
| --- | --- | --- | --- |
| `tencent`（**现在用这个**，2026-10-25 他定的） | 腾讯云上海默认地址 | 同一个地址（默认就回 `attachment`） | 国内快：他在杭州、微信里实测起播 1.0 秒、9.1 Mb/秒。按流量收费 |
| `cloudflare` | `media.praxisai.online` | 同一地址加 `?download=1` | 不收流量费。国内被分到洛杉矶、西雅图、阿姆斯特丹、伦敦等海外节点，实测 4.2 秒、4.2 Mb/秒，低于片子约 7 Mb/秒，分到远的节点会卡 |

**他的规则（2026-10-25）**：用哪一套由他拍板。另一套只在当前这套**完全用不了**时自动顶上（停服、欠费、报错，或点播放 10 秒连片子的文件头都没拿到），**卡顿、慢都不换**。两站的 `site.js` 都这样做，`scripts/test-player.cjs` 逐种情况验证：报错、不回应、播到一半断掉要换；慢、卡住、只给文件头不给画面不换。

## 只改一个地方
- 唯一的设置：影片仓库 `src/hosts.json`（`active` 写 `tencent` 或 `cloudflare`，以及两套的播放、下载地址）。影片网站构建时读它，并发布一份 `https://qinxujunai.github.io/too-late-to-love-you/hosts.json`。
- 个人网站不写地址：`scripts/film-hosts.mjs` 把发布出去的那份抄进 `src/film-hosts.json`（不要手改它）。`npm run ship` 每次先抄（抄不到就不上线）；每 6 小时的定时任务也抄一次，变了就重建，所以就算没人上线，最晚 6 小时也会跟上。
- 防止只换了一个：个人网站的 `check` 发现自己的 `film-hosts.json` 和旁边影片仓库的 `src/hosts.json` 不一样就不通过；每周一的外链体检发现两站线路不一样就失败，GitHub 发邮件给他。

**先后顺序**：个人网站要读影片网站已经发布的 `hosts.json`，所以凡是改了影片仓库 `src/hosts.json`，都先上线影片网站、等发布完（一两分钟），再上线个人网站。`npm run host` 会自动按这个顺序做。

## 换方案：一条命令
在影片仓库：
```bash
npm run host -- cloudflare     # 或 tencent
```
它会：先确认那一套的播放、下载地址都能拿到这个文件（大小、MD5 一致，下载地址回 `attachment`），不行就什么都不改；影片仓库有别的没提交的改动时也不动手；改 `active`、上线影片网站；等发布出去的 `hosts.json` 变了，再上线个人网站（在 `$PERSONAL_SITE` 或 `../qinxujunai.github.io` 找；找不到就打印要在那边运行的一条命令）。中途失败可以直接重跑。上线前的验收只要求**要切过去的那一套**是好的，另一套坏了只报警告，所以当前这套挂掉时照样能切走。

## 两处存储
**腾讯云：轻量对象存储（Lighthouse 版），上海**
- 存储桶 `media-1416754078`，按量计费（他买过一个 1GB 流量包）。管理入口在「轻量应用服务器 → 对象存储」，不在「对象存储 COS」控制台（那里显示「暂无数据」是正常的）。
- 访问权限「公共读私有写」，视频文件单独设了公共读：匿名能读，列不出也写不进（403）。
- 文件头：`Content-Type: video/mp4`、`Cache-Control: public, max-age=31536000, immutable`。2024 年以后建的桶，默认域名会带 `Content-Disposition: attachment` 和 `x-cos-force-download: true`：直接打开会下载，在网页 `<video>` 里（含微信）照常播放，验证过。
- 这类桶是「role mode」：用接口改桶的 ACL 或策略会被拒绝；改单个文件的 ACL 要主账号密钥，或在控制台对文件点「权限」。
- 没有防盗链功能，也不能按 IP 限次数。

**Cloudflare：R2**
- 他的 Cloudflare 账号，存储桶 `media`，自定义域名 `media.praxisai.online`（域名 praxisai.online 在他的账号里，免费版）。`r2.dev` 测试地址国内常被拦，不要用。
- 下载规则（2026-10-25 加的）：区域 praxisai.online 的「响应头转换规则」里一条「film download: attachment only for ?download=1」，只给 `/too-late-to-love-you.mp4?download=1` 加 `Content-Disposition: attachment`；不带参数的播放地址不受影响。跨站的下载链接只有服务器回 `attachment` 才会真的下载（网页上的 `download` 属性对别的网站无效）。
- 不收流量费，只在节点没缓存、回 R2 读文件时计读取次数（每月前 1000 万次免费）。国内的播放实测全部命中缓存。用 R2 放视频是 Cloudflare 条款允许的（2023 年起，视频放在 R2 上可以走它的 CDN）。

## 关键的技术约束
- **地址写在 `<video>` 自己的 `src` 上，不用 `<source>` 子元素**：微信安卓用腾讯 X5/XWeb 内核接管视频，只读 `src`（2026-10-24 用 `<source>` 时微信里放不出来）。两站的 `check` 都会拦。
- `preload="none"`：不点播放不下载。
- 本仓库和影片仓库里都不再放视频文件（2026-10-25：国内不开 VPN 连不上 GitHub Pages，那一份做备用没用）。
- QQ 浏览器里只有声音、没有画面，是 QQ 浏览器的问题，微信和系统浏览器正常。别因为这个去动片子。

## 换片子文件时（他提供新文件后）
1. 原样替换，不做任何处理。
2. 腾讯云：同名上传 `too-late-to-love-you.mp4`，带上面的两个文件头，再把文件设成公共读。上传时关掉 aws-chunked 编码，否则文件头里会多出 `Content-Encoding: aws-chunked`。
3. Cloudflare：同名上传，`Content-Type: video/mp4`。
4. 更新影片仓库 `src/hosts.json` 的 `file`（字节数、SHA-256、MD5；两边返回的 ETag 就是 MD5）。两站的 `npm run qa` 会核对两处都是这个文件。
5. 腾讯云让浏览器缓存一年：要立刻生效，就换个文件名，同时改 `src/hosts.json` 里两套的地址。

## 试过、不要再走的路
- B 站嵌入、线路开关（v26.6–26.8，手机上卡死；他说不要新按钮、不要跳转 B 站）。
- 按卡不卡自动换线路、测速选线路（2026-10-25 他否了：两套方案二选一，完全用不了才换）。
