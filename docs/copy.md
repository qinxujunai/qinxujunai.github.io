# 文案平台

文字本身只在 `src/content.mjs`（首页）和 `src/cases.mjs`（案例）里。这份文档写的是：为什么这样写，每句话出自哪里，以后怎么改。

## 定位（v5，2026-10-20）
- **读者**：第一次在微信里点开链接的陌生人。可能是同行，可能是想找他合作的人，也可能只是好奇。
- **他们要带走什么**：5 秒知道这是一个用 AI 做东西、也愿意分享做法的人；30 秒看到他做的真东西；离开时觉得他靠谱、好相处，并加上微信。
- **骨架**：三个作品（每个都是能点开的网站）、一份分享（ai.vibecoding）、一个人（经历、照片、结尾）。

## 语气
他说过：「太夸张了，搞得像面试一样」「不是 Demo 而是交付这种话很傻」「别说啥把项目问题带过来」。所以：
- 像对朋友介绍自己，不像对面试官，也不像在揽活。参照 rauchg.com、karpathy.ai：第一人称，平静，短。
- 一个作品只说一件事：它为你做了什么，用一句人话。首页不放 KPI 大数字，数字和架构留在作品页。
- 不用口号式对仗（「不是 X，是 Y」），不用「交付」「落地」「方案」「闭环」这类汇报词。
- 能用他的原话，就不用我写的口号。
- 每句话都要经得起同行核对：和线上网站、仓库文档对得上。

## 口吻
- 冷静、具体、有温度。像一个做过很多事的人，在讲自己做过的事。
- 一句只说一件事。先说对方能得到什么，再说我做了什么。
- 用数字和例子代替形容词，每个结论旁边都有证据。
- 不用「赋能、打造、极致、顶级、助力、颠覆、闭环生态」。
- 不自夸「最强」，宁可写「还差什么」。
- 英文是按同一个意思重写的，不是直译。

## 写完自查：每一句都问三个问题
1. 删掉它，读者会少知道什么？什么都不少，就删。
2. 能不能换成一个数字或一个例子？
3. 出处在哪？

## 案例标题
- 每个标题都是一个结论；副标题说清楚为谁做、解决什么问题。
- 章节标题用动词或问句：为什么要做 / 难在哪里 / 边界 / 架构 / 我放弃了什么 / 怎么证明它可靠 / 时间线 / 还差什么。
