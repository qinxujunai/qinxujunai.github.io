# 文案平台

文字本身只在 `src/content.mjs`（首页）和 `src/cases.mjs`（案例）里。这份文档写的是：为什么这样写，每句话出自哪里，以后怎么改。

## 定位（v5，2026-10-20）
- **读者**：第一次在微信里点开链接的陌生人。可能是同行，可能是想找他合作的人，也可能只是好奇。
- **他们要带走什么**：5 秒知道这是一个用 AI 做东西、也愿意分享做法的人；30 秒看到他做的真东西；离开时觉得他靠谱、好相处，并加上微信。
- **骨架**：三个作品（每个都是能点开的网站）、一份分享（ai.vibecoding）、一个人（经历、照片、结尾）。

## 不对读者说教（v27.3，2026-10-24，最高优先级）

他说：「苹果官网它会来一句说：『你是这样，你什么什么人』……它会这样说话吗？」「你不要说『听这三个人』……显得你很傲慢。」

**为什么反复出问题**：他在对话里说的话，是对一个具体的人说的建议（「迷茫的时候，就做三件事」「去听那些你想成为的人的建议」）。原样搬进标题和副句，就变成网站对每个读者下指令、给人分类。v27 的「就做三件事」「也听这三个人」「照着练就行」「为自己要成为什么样的人」都是这样来的。

**规则**：
1. 标题、副句说**这里有什么、他做了什么**，不说读者该怎么活。「迷茫的时候，就做三件事」→「迷茫的时候，我会做三件事」；「有一份计划，照着练就行」→「健身，我推荐这套三分化」。
2. **不给人分类、不居高临下**：不写「什么样的人」「那种人」「这三个人」「优秀的人」。人用名字或身份（「三位抖音博主」）。
3. 他的建议只出现在**有署名的引文里**（「它改变了我」「我为什么推荐」「为什么做」、结尾的信），而且是他讲自己的经历；引文里对读者说的「你」删去，用「……」标出。
4. 不用格言做副句（「重要的是为了……」「想法本身没有任何价值」）。格言改成第一人称的事实，或者删掉。
5. 产品网站里的服务口吻（「给你文字」「替你读一遍」）不算说教，可以用。

**写完自查**：把每个标题读给一个陌生人听——它是在介绍一样东西，还是在教他做人？后者就改。`npm run check` 里的 voice 检查会拦已知的说法（`scripts/check.mjs` 的 `LECTURE`），新发现的说法要加进去。

## 文案标准（v6，对标 apple.com.cn）
他说：「对所有文字都用这种标准审视一遍……就拿苹果去对标，用苹果的所有标准去做这个网站。」以下规则来自实测 apple.com.cn（MacBook Air、AirPods Pro）以及 brianlovin.com、emilkowal.ski、paco.me 的首屏：
0. **3 秒前置**（他反复强调）：每个区块的第一句就回答「这是什么 / 解决什么」，像短视频开头；先说解决的问题，再说怎么做。
1. **层级固定**：小标签（两个字：分享、经历、影像；作品页：起因、难点、边界、架构、取舍、验证、历程、还差什么）→ 一句短标题 → 一段正文。
2. **标题说事实或好处，不喊口号**：不用方法论、两拍口号、双关、自评（如「懂人」「顶级」）。好标题是「按一下，说话，文字就出现在光标处。」「一张人台照，变成一组模特图。」
3. **首屏**由他本人定：头像、签名、大标题、作品清单、两个动作。不再改动。
4. **不重复**：相邻元素不说同一件事（标题和第一条经历不能都写「金融、政企」；介绍和信息行不能都写「三条路线」）。
5. **一段一件事**，先说对读者有什么用，再给数字；数字都有出处（见 `src/cases.mjs` 注释）。
6. **首页不用术语**：剪贴板核对、编号回填、RTF 这类只放在作品页，并配白话解释；状态机之类的写法不上页面。
7. **用词统一**：链接一律「访问网站 ›」「进一步了解 ›」「开始阅读 ›」；作品卡说明一律是名词短语。
8. **人称**：首页面向所有人，不用「你」去指挥读者（「让你守住……」→「让人守住……」）；产品说明不写「在你自己的电脑上」，写「本机」。只有直接对读者说话的句子（「谢谢你看到这里」）用「你」。
9. **作品区块两级文字**（刘）：图上方只有名字和一句大白话（它是什么、帮你做什么）；事实和链接放图下方。一句话要像短视频三秒能懂，不写「Windows · 离线 · 免登录」这种代号式小字。
10. **标点**：标题、副句、单行说明、图片说明、名片、提示语不带句末句号；多句正文保留。
11. **克制**：不用感叹号、不用「赋能、打造、极致、顶级、助力、颠覆」；他的原话只用 2026-05 的版本。

## 语气
他说过：「太夸张了，搞得像面试一样」「不是 Demo 而是交付这种话很傻」「别说啥把项目问题带过来」。所以：
- 像对朋友介绍自己，不像对面试官，也不像在揽活。参照 rauchg.com、karpathy.ai：第一人称，平静，短。
- 一个作品只说一件事：它为你做了什么，用一句人话。首页不放 KPI 大数字，数字和架构留在作品页。
- 不用口号式对仗（「不是 X，是 Y」），不用「交付」「落地」「方案」「闭环」这类汇报词。
- 能用他的原话，就不用我写的口号。
- 每句话都要经得起同行核对：和线上网站、仓库文档对得上。

## 口吻
- 冷静、具体、有温度。像一个做过很多事的人，在讲自己做过的事。
- 一句只说一件事。先说对方能得到什么，再说我做了什么。
- 用数字和例子代替形容词，每个结论旁边都有证据。
- 不用「赋能、打造、极致、顶级、助力、颠覆、闭环生态」。
- 不自夸「最强」，宁可写「还差什么」。
- 英文是按同一个意思重写的，不是直译。

## 写完自查：每一句都问三个问题
1. 删掉它，读者会少知道什么？什么都不少，就删。
2. 能不能换成一个数字或一个例子？
3. 出处在哪？

## 案例标题
- 每个标题都是一个结论；副标题说清楚为谁做、解决什么问题。
