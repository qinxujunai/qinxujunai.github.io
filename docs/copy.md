# 文案平台

文字本身只在 `src/content.mjs`（首页）和 `src/cases.mjs`（案例）里。这份文档写的是：为什么这样写，每句话出自哪里，以后怎么改。

## 定位
- **读者**：需要把 AI 真正落地的团队。可能是招 AI 解决方案、AI 产品或 AI 项目负责人的用人经理，也可能是带着具体问题来找他的人。
- **他们缺什么**：一个既能把方案讲清楚、又能亲手把它做出来的人。
- **一句话承诺**：从一句话，到能用的 AI。
- **三根支柱**：
  - **想得清**：思考区的三种能力，用的都是他的原话。
  - **做得出**：VoiceFlow、AI Signal、万象成文，都是他一个人做的。
  - **交得了**：比智的方案到回款，一念的飞书智能体，微众银行项目的逆转。

## 语气（v4.3，2026-10-20）
他看了首页说：「太夸张了，搞得像面试一样」「不是 Demo 而是交付这种话很傻」。从这一版起：
- 像对朋友介绍自己，不像对面试官。参照 rauchg.com、karpathy.ai、paulgraham.com：第一人称，平静，短。
- 一个作品只说一件事：它为你做了什么，用一句人话。首页不放 KPI 大数字，数字和架构留在详情页。
- 不用口号式对仗（「不是 X，是 Y」），不用「交付」「落地」「方案」「闭环」这类汇报词。
- 能用他的原话，就不用我写的口号。

## 口吻
- 冷静、具体、有温度。像一个做过很多事的人，在讲自己做过的事。
- 一句只说一件事。先说对方能得到什么，再说我做了什么。
- 用数字和例子代替形容词，每个结论旁边都有证据。
- 不用「赋能、打造、极致、顶级、助力、颠覆、闭环生态」。
- 不自夸「最强」，宁可写「还差什么」。
- 英文是按同一个意思重写的，不是直译。

## 写完自查：每一句都问三个问题
1. 删掉它，读者会少知道什么？什么都不少，就删。
2. 能不能换成一个数字或一个例子？
3. 出处在哪？

## 案例标题
- 每个标题都是一个结论；副标题说清楚为谁做、解决什么问题。
- 章节标题用动词或问句：为什么要做 / 难在哪里 / 边界 / 架构 / 我放弃了什么 / 怎么证明它可靠 / 时间线 / 还差什么。

| 案例 | 标题 | 关键数字的出处 |
|---|---|---|
| VoiceFlow | 说完就上屏，一个字都不丢。 | VoiceFlow 仓库 `docs/`：发布性能证据、ADR、发布记录 |
| AI Signal | 几百条 AI 资讯里，替我挑出值得看的那几条。 | ai-signal README（「每天几百条信息，真正值得看的不到 5 条」）、成本表 |
| 万象成文 | 一个链接进去，可用的文字出来。 | Audio2Text README、AGENTS.md、`docs/transcription-benchmark.md` |
