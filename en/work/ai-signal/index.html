Why build it

There is too much AI news: posts, podcasts, blogs, papers, GitHub. Hundreds of items a day, and fewer than five worth reading. Scrolling a feed costs time and lets noise set the mood.

I wanted a dependable editor: someone who reads everything each day and keeps only what would change a decision, in three minutes.

What made it hard

  • Models make things up. Let one write links and numbers and sooner or later a convincing fake appears.
  • The same story shows up on a blog, on Hacker News and on X at once. Without merging, it repeats.
  • It can stop silently. After 2026-07-22, GitHub paused the schedule because the repository had no commits for 60 days. The briefing stopped for almost three months with no error anywhere.
  • Old sources rot: the third-party GitHub Trending API died, a Chinese media RSS feed disappeared, and the old feedback buttons pointed at a service returning 404.

Scope

Does

  • Aggregate public sources
  • Select, merge and rewrite to a fixed editorial brief
  • One email and one web issue a day, every item linked

Does not

  • Require X or YouTube API keys
  • Build an app or accounts
  • Track readers: no pixels, no click counting

Architecture

  1. 1Collect · prepare-digest

    • Builders on X and podcasts (follow-builders)
    • OpenAI, DeepMind, Google AI, Hugging Face blogs
    • Hacker News: last 36 h, 60+ points
    • HF Daily Papers, GitHub Trending, QbitAI
    • Drop anything sent in the last 60 days

  2. 2Number

    • Every item gets an ID: H3, P1, G2…

  3. 3Edit · DeepSeek

    • Select by three questions, merge sources
    • JSON only, IDs only

  4. 4Resolve · remix-digest

    • Code fills in links, scores and stars by ID
    • Unknown ID: the item is dropped
    • Model down: a ranked fallback issue

  5. 5Deliver · deliver

    • The subject line is the day’s headline
    • Web edition and sent list committed back

The editorial standard lives in the prompt. Every item must pass three questions: Would the reader decide differently because of it? Is it a new fact or noise? Does it carry a concrete number or name?

The layout follows TLDR, The Rundown and Axios: one column, headlines that state facts, one source line under every item, and ranked two-column lists for papers and repositories.

What I gave up

  • The model cites IDs, never links

    WhyLinks and numbers are the easiest things to invent; filled in by code, they cannot be wrong

    Given upLet the model write them and check afterwards

  • Commit the web edition every day

    WhyIt is the archive, and it keeps the schedule from being paused after 60 quiet days

    Given upEmail only, no trace

  • Remove 👍 / 👎 and the tracking pixel

    WhyThe feedback service had been returning 404; keeping them meant broken links

    Given upPretending there is a feedback loop

  • Hacker News through Algolia, whole-word matching

    WhyThe old code read 30 front-page stories and matched substrings, so “said” counted as AI

    Given upThe front-page API

  • DeepSeek’s chat model

    WhyAbout $0.003 a day

    Given upA pricier reasoning model

How I know it holds up

  • The first v3 issue (2026-10-20) picked 30 of 60 new items, went out by email, and published a web edition and archive.
  • Every link and number comes from the raw data; an item that cites an unknown ID never appears.
  • If the model is down, an issue still goes out, ranked by source signal and labelled as such; a failed source is named in the footer.
  • Sent links are remembered for 60 days, so nothing repeats.

Timeline

  1. 2026.05First version: follow-builders posts and podcasts, LLM curation, email
  2. 2026.05.22v2: Hacker News, ArXiv, GitHub and Chinese media added
  3. 2026.07.22Last automatic send; the schedule was then paused after 60 days without commits
  4. 2026.10.20v3: new sources, editing and layout; daily sends restored

What’s still missing

  • Posts and podcasts still depend on the third-party follow-builders feed.
  • Reddit refuses automated requests, so community discussion comes only from Hacker News.
  • QbitAI is the only Chinese source.
  • There is no reader feedback loop; the editorial brief improves only when someone reads and edits it.
